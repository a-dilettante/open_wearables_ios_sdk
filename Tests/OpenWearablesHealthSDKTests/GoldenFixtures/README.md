# Workout-owned detail golden fixture

Generated by `EnrichmentGoldenFixtureTests` from a deterministic synthetic workout, by
running the real `EnrichmentPreparation` → `EnrichmentManifestBuilder` → `EnrichmentOutbox`
pipeline. These are the actual wire bytes an upload would send.

**Never hand-edit these files.** Regenerate them:

```
OW_REGENERATE_GOLDEN=1 xcodebuild test -scheme OpenWearablesHealthSDK \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:OpenWearablesHealthSDKTests/EnrichmentGoldenFixtureTests
```

The same bytes are committed in the open-wearables backend at
`backend/tests/fixtures/workout_owned_detail_golden/`, where
`tests/api/v1/test_workout_detail_golden_conformance.py` replays them through the live
endpoints and asserts the server recomputes exactly the family hashes this manifest
declares. If a hash recipe drifts on either side, that test fails — which is the point of
committing bytes rather than a generator.

| File | What it is |
| --- | --- |
| `manifest.json` | The upload manifest, exactly as `PUT .../uploads/{upload_id}` sends it |
| `*.json.gz` | One gzip-compressed columnar chunk, exactly as `PUT .../chunks/{family}/{index}` sends it |
| `expectations.json` | Upload id, root hash, per-family hashes, and every chunk's checksum, byte count and upload address |

Everything here is synthetic: invented coordinates near (45, 9), an `00000000-…`-shaped
workout UUID, and a `com.example.goldenrecorder` bundle id. No real person, device or
location is represented.
